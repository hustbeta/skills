# 异步资源变更与业务元数据同步设计（脱敏快照）

## 目标与约束

- 提供虚拟资源规格变更接口，并让业务侧规格查询尽快显示目标值。
- 继续使用基础设施提供方现有异步 resize API。
- 不新增消息队列、数据库表或外部依赖。
- 验证不得通过重放生产 resize 请求完成。

## 拟议流程

1. 校验资源当前状态允许 resize。
2. 向基础设施提供方提交目标规格。
3. 提交调用正常返回后，立即把业务表中的有效规格覆盖为目标磁盘、内存和 CPU。
4. 返回接口成功；后续基础设施状态由现有运维页面独立展示。

业务表只保存一组有效规格，不区分 requested、pending 和 effective。基础设施后续失败时，由运维人员按告警人工修正业务表，本次设计不增加自动对账。

## 验收方案

- 合法资源提交 resize 后，接口成功且业务查询立即返回目标规格。
- 不允许 resize 的资源状态返回校验错误，业务表不变。
- 提交调用同步抛错时，业务表不变。
- 现有资源列表和详情页继续读取同一业务表字段。

## 非目标

- 不改变基础设施提供方的状态机。
- 不新增事件总线或强制采用轮询。
- 不在测试中执行真实生产资源变更。
