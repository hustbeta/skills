# 脱敏证据

本附件是自包含的合成证据，不对应任何真实产品或生产数据。

## E9-01 滚动拓扑

发布平台一次只替换部分实例。正常滚动窗口内旧版本和新版本会同时接收创建、更新和调度请求；现有发布材料没有要求在读切换前完成旧版本实例清退。

## E9-02 两类 writer

- 旧版本 writer 只更新 `execution_pool_name`，不了解 `execution_pool_id`。
- 新版本 writer 从不变的 API 名称解析目录，同时更新 `execution_pool_name` 和 `execution_pool_id`。
- 两类 writer 都可能更新同一张 `scheduled_tasks` 表。

## E9-03 一次性回填

回填任务只执行一轮：扫描当时满足 `execution_pool_id IS NULL` 的记录，按读到的名称查目录，再按任务主键更新 ID。更新语句不比较回填读取时的名称、记录版本或更新时间。扫描到表尾后设置单一完成标志；没有增量追赶、重复扫描或漂移计数。

## E9-04 旧 writer 门禁

拟议 cutover 只检查 `backfill_completed=true`。附件没有实例清单、最低版本门禁、旧 writer 写入拒绝机制或证明旧版本已经停止写入的其它条件。

## E9-05 新 reader

新调度器切换后只读取 `execution_pool_id`，不回退读取名称。ID 为空时选择平台默认执行池；找不到对应 ID 时该任务本轮调度失败。

## E9-06 可观察后果

历史任务可以指定非默认执行池。若记录名称仍指向非默认池但 ID 为空，新调度器会选择不同的默认池；需要专用能力而默认池不具备时，调度会持续失败。任务记录保留该空 ID，后续扫描会重复相同行为，直到数据被修复。

## E9-07 历史别名与运行证据

历史数据中存在少量别名，其中同一别名曾被两个仍有效的执行池使用；当前附件没有足够业务归属信息确定每条记录应映射哪个 ID。附件也没有真实生产实例清单、流量、表规模、目标环境执行结果或部署结果。
