# 外部日期口令 API 设计（脱敏快照）

## 背景与目标

系统已有三个按日期计算六位口令的内部功能。现需新增三个版本化 POST API，供外部客户端计算领域 A 离线口令、领域 B 卸载口令和领域 B 网络解锁口令。

目标：

- 复用现有外部 API 客户端、用户权限和 HMAC 安全边界；
- 严格校验日期，不允许非法输入回退到服务器当前时间；
- 保持六位字符串及前导零；
- 不保存输入日期、签名摘要或生成口令；
- 抽取稳定安全流程，避免复制第三套认证实现。

## 已确认决策

| 事项 | 决策 |
| --- | --- |
| 客户端 | 复用现有 `ExternalApiClient` 及其加密密钥 |
| 权限 | 复用 `user.call_external_api`，不新增权限或 migration |
| 路径 | 使用领域 A/B 业务路径，不迁入既有工具 API 路径 |
| 输入 | 必填、单字段严格 JSON，按 `Asia/Shanghai` 解释 |
| 输出 | `{"code":0,"data":{"passcode":"012345"}}` |
| 审计 | 不写业务审计；安全失败只记录非敏感元数据 |
| 基础设施失败 | Redis、密钥解密等必要依赖异常时失败关闭 |
| 旧内部接口 | 保持现状，未认证旁路作为已接受风险 |

## API 契约

```text
POST /api/v1/domain-a/offline-password/
POST /api/v1/domain-b/uninstall-code/
POST /api/v1/domain-b/network-unlock-code/
```

请求使用五个签名头：客户端 ID、Unix 时间戳、32 位随机 Nonce、请求 UUID 和 HMAC-SHA256 签名。服务端要求：

- 客户端存在且密钥可解密；
- 归属用户存在、启用并拥有 `user.call_external_api`；
- 时间戳在服务端时间 `±300` 秒内；
- 客户端 Nonce 原子登记 600 秒，重复值拒绝；
- 来源 IP 每分钟 30 次、客户端每分钟 60 次，桶容量均为 10；
- Redis 异常时不继续计算口令；
- 所有响应包含 `Cache-Control: no-store` 和请求 ID。

领域 A 离线口令与领域 B 网络解锁口令只接受 `{"date":"YYYY-MM-DD"}`；领域 B 卸载口令只接受 `{"datetime":"YYYY-MM-DD HH:00:00"}`。正文上限 1024 字节，禁止重复、缺失或额外字段、无效公历日期、时区后缀及非整点时间。

## 安全处理顺序

1. 校验方法、Query String、媒体类型、字符集和 `Content-Length`。
2. 生成或规范化请求 ID，取得可信来源 IP并执行 IP 限流。
3. 有界读取正文，拒绝超过 1024 字节的请求。
4. 严格解析唯一 JSON 字段并构造规范正文摘要。
5. 验证客户端、归属用户、权限及 HMAC。
6. 校验时间窗，执行客户端限流并登记 Nonce。
7. 校验真实日期，调用现有算法并返回六位字符串。

共享安全模块只处理请求读取、规范摘要、认证、限流、Nonce 和固定响应，不理解具体日期业务。三个口令视图分别负责输入语义和算法映射，不建设通用业务引擎。

## 日志、兼容与回滚

- 成功不记录；失败日志只允许请求 ID、合法客户端 ID、可信来源 IP、固定失败类型和时间。
- 不记录正文、日期、摘要、签名、Nonce、密钥或口令。
- 现有工具 API 的路径、签名、响应和审计保持不变。
- 旧三个内部 GET 接口保持原路径、参数、响应和认证现状。
- 本设计无数据库迁移和新配置；回滚恢复应用代码并重启即可。

## 非目标与已接受风险

- 不新增接口级 scope 或独立授权开关；所有现有有效客户端自动获得新 API 能力。
- 不修复旧内部 GET 接口的未认证旁路。
- 不新增业务审计表，不记录口令 hash。
- 不建设通用外部 API 框架，不新增第三方依赖。
- 不提供应用层响应加密；传输机密性由 HTTPS 或等价信道保证。

## 验证标准

- 合法签名和日期返回六位字符串，结果与现有算法一致。
- 非法 JSON、日期、方法、媒体类型、签名、时间窗、Nonce、限流和依赖失败返回固定错误。
- 成功与业务失败均不产生业务审计，安全日志不含敏感字段。
- 现有工具 API 和旧内部 GET 接口回归行为不变。
- 不以启动本地服务作为验证方式；使用目标测试集验证共享安全和三个新 API。
